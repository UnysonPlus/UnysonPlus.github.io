# Headless WordPress with plain JavaScript

You don't need a framework to use WordPress headless. Two HTML pages, a few JavaScript modules and a
stylesheet are enough: the browser asks the WordPress REST API for the content and builds the page
itself. Nothing to install and no build step, which makes this the clearest way to see how a headless
site works.

This example lists **books** from a WordPress site and gives each one its own page. The book post type
and its fields come from Unyson+ (see [Headless WordPress with Unyson+](./unysonplus-headless.mdx)), but
the front-end code is the same for any WordPress site: only the name of the fields object changes.

## How it fits together

- **The HTML is a shell.** `index.html` has an empty list and a `<template>` for one book card;
  `book.html` has an empty article. Neither contains any content.
- **One file talks to WordPress.** `js/wordpress.js` holds the fetch helper and one function per
  query (`getBooks`, `getBook`, `getGenres`). The pages call those functions and never build a REST URL
  themselves.
- **Ask only for what you use.** Every request passes `?_fields=`, so WordPress sends back just the
  fields the page shows.
- **Each page script fills its page.** `js/books.js` copies the card template once per book;
  `js/book.js` reads `?slug=` from the address, fetches that one book and fills in the article.
- **Titles and content arrive as HTML.** A title can contain entities (`&amp;`), so it is converted to
  plain text before it goes into `textContent`. The post body is your own site's HTML and is inserted
  as it is.

## Run it

1. Download the example and set your site's address in `js/config.js`.
2. Serve the folder with any static web server: `npx serve .` or `python -m http.server`.
3. Open the address it prints.

Opening `index.html` straight from the disk does not work: browsers only load JavaScript modules from
a web address. The pages can live on any domain, because WordPress lets other sites read its public
REST API.

## When to choose plain JavaScript

| | Plain JavaScript | [Next.js](./headless-nextjs.mdx) |
|---|---|---|
| Setup | None: any static host | Node.js, a build, a host that runs it |
| Who builds the page | The visitor's browser, on every visit | The server, ahead of time |
| Search engines | See "Loading…" first, the content after the script runs | See the finished page |
| Good for | Small sites, a widget inside another site, learning the API | Full websites where search ranking and first load matter |

The two examples are deliberately the same shape: compare `js/wordpress.js` here with
`lib/wordpress.ts` in the Next.js example and the requests are identical.
