# Headless WordPress with Next.js

Next.js is the most common front end for headless WordPress. This example is a small but complete
App Router site: it lists **books** from a WordPress site, gives each book its own page with its title,
description and cover as page metadata, and refreshes from WordPress at most every five minutes.

The book post type and its fields come from Unyson+ (see
[Headless WordPress with Unyson+](./unysonplus-headless.mdx)). With another setup only the name of the
fields object changes: `acf` with ACF, `unysonplus_fields` with Unyson+.

## How it fits together

- **One file talks to WordPress.** `lib/wordpress.ts` knows the API's address, describes the shape of
  the responses as TypeScript types, and has one function per query. Pages never build REST URLs
  themselves.
- **Ask only for the fields you use** with `?_fields=`, so responses stay small.
- **Pages are server components.** They `await` those functions and render the result, so the HTML
  that reaches the browser (and search engines) already holds the content.
- **Built ahead of time, refreshed in the background.** `generateStaticParams` builds every book page
  at build time; `revalidate: 300` lets Next.js fetch fresh data at most every five minutes. To update
  the moment an editor publishes, call a revalidation route from a WordPress webhook (on the
  [roadmap](./roadmap.md) for the Headless extension).
- **Metadata from WordPress.** `generateMetadata` turns the book's title, subtitle and cover into the
  page title, description and sharing image.

## Run it

```bash
cp .env.example .env.local   # then set WP_URL to your WordPress site
npm install
npm run dev                  # http://localhost:3000/books
```

`npm run build` generates every book page ahead of time. This example was built against a test site
running the Book post type described in the Unyson+ tutorial.

## Next.js or plain JavaScript?

Next.js builds the pages on the server, which suits full websites where search ranking and first load
matter. For a small site, a widget inside another site, or to learn the API, the
[plain JavaScript version](./headless-javascript.mdx) does the same with no build step, and its
`js/wordpress.js` makes the same requests as `lib/wordpress.ts` here.
