# Shop roadmap

Shop is a planned online store built into Unyson+ itself, not on top of another store plugin. It is being built
for one reason: **one customer, one checkout and one record across the whole site.** Someone who buys a product,
joins a plan, books a room and fills in a paid form is one contact in the [CRM](/crm), with one account page,
one payment history and one set of invoices.

Status is checked against the extensions' files automatically, so a task shows as done only once its code exists.

## Phase 0 · Payments

The store is built on one shared [Payments](../payments) extension, so that comes first. Its first version
(one-off payments through Stripe, PayPal and bank transfer or cash) is built.

## Order of work

0. **One payments core.** Forms and [Membership](/membership) each carry their own Stripe, PayPal and offline
   gateways and their own coupons. Before a store adds a third copy, they become one shared **Payments**
   extension: one provider interface, one ledger, one set of invoices, tax and coupons. Membership, Forms and
   Bookings move onto it, and sites already taking payments keep working. Then the local providers: PayMongo
   for the Philippines (GCash, Maya, QR Ph), Xendit for Southeast Asia, and more regions as shops ask for them.
1. **The catalogue**: physical, digital and service products, options and variants, stock, extra fields
   from Custom Fields, Import / Export, and **catalog mode**, a shop that shows products and takes enquiries
   without selling. It can ship before the cart exists.
2. **Cart and checkout**: guest or account checkout on one page, delivery zones and rates, and order emails.
3. **Running the orders**: statuses, refunds, tracking, invoices, and *My orders* inside the member area.
4. **Designed in the page builder**: store elements, Theme Builder templates and starter pages.
5. **Connected to every Unyson+ extension**: CRM, Membership, Bookings, Forms, SEO, Visitor Insights,
   POS Sync, the AI Assistant and Chat.
6. **Selling more**: abandoned cart recovery, subscribe and save, bundles, upsells, gift cards, reviews and
   wishlists.
7. **Reports, privacy and moving in**, including a WooCommerce importer.

## Where payments live

Payments is its own extension, hidden from the Extensions list. No extension requires it. It is installed and
switched on the first time a feature needs to take money:

| Extension | What switches Payments on |
| --- | --- |
| Shop | Selling is switched on (catalog mode off) |
| Membership | Its Payments module is switched on |
| Forms | A form gets a Take payment action |
| Bookings | A bookable gets a deposit |

So a catalog-mode shop, a free members site or a contact form never loads payment code. Once on, Payments adds
one screen for provider keys, the ledger, invoices, tax and coupons, and it stays installed, because it holds
the payment records an owner has to keep.

Each **provider** is written once and brings its **methods** with it. Checkout shows a customer only the methods
that fit the order's country and currency: GCash for an order in pesos, iDEAL for a customer in the Netherlands.
Most e-wallets are one-off payments, so renewals and repeat deliveries are offered only on methods that can
charge again, such as cards.

## Shop and the WooCommerce extension

The [WooCommerce extension](../woocommerce/) is not going away. Sites that run WooCommerce keep using it, with
its page-builder elements and shopper tools. Shop is for sites that want the store, the memberships, the bookings
and the CRM to be one system. Phase 7 brings an importer for moving a WooCommerce store across.

## How this page stays current

`src/data/shop-roadmap.json` and `src/data/payments-roadmap.json` list every task with a `detect` block naming the files that make it real, and
`scripts/gen-roadmap.mjs` checks them against the extension's source tree:

```bash
npm run roadmap:payments        # Phase 0
npm run roadmap:shop            # scan and rewrite the JSON
npm run roadmap:shop -- --dry   # report only, write nothing
npm run roadmap:shop -- --check # exit 1 if stale
```

The `detect` paths are also the agreed file layout: core classes in `includes/`, connections to other
extensions in `includes/integrations/`, switchable modules in `modules/<module>/`, page-builder elements in
`shortcodes/<name>/`. Phase 0 has its own file because it belongs to
the shared Payments extension.
