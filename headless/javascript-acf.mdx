# Headless WordPress with JavaScript, ACF and CPT UI

<LastUpdated />

The most common headless setup, without a framework: **Custom Post Type UI** registers the content type,
**Advanced Custom Fields (ACF)** adds the fields, and two plain HTML pages fetch everything from the
WordPress REST API in the browser. Nothing to install on the front end and no build step.

The example is a small book site: a list of books, and a page per book.

<p><small>The same front end with Unyson+ instead of the two plugins:

## 1. Before you start

You need:

- **A WordPress site** you can log in to as an administrator: on any host, or on your own computer (LocalWP, XAMPP). It needs to be reachable from wherever the front end runs.
- The free plugins **Custom Post Type UI** and **Advanced Custom Fields** (step 2 installs them).
- **A text editor**, and a way to serve a folder over HTTP for testing: Node.js (`npx serve`) or Python (`python -m http.server`).

About 15 minutes for WordPress, and 10 for the front end.

## What the API returns

ACF puts the fields under **`acf`** on each post. By default an Image field comes back as just the
attachment ID. Add **`acf_format=standard`** to the request and ACF returns each field in its Return
Format instead, so the cover arrives as an object with its URL, size and alt text:

```bash
curl "https://your-site.com/wp-json/wp/v2/book?slug=the-quiet-garden&_fields=id,slug,genre,acf&acf_format=standard"
```

```json
[
  {
    "id": 3660,
    "slug": "the-quiet-garden",
    "genre": [258],
    "acf": {
      "subtitle": "A year among the weeds",
      "book_author": "Sam Rivera",
      "pages": "248",
      "cover_image": {
        "id": 3659,
        "url": "https://your-site.com/wp-content/uploads/2026/10/quiet-garden-cover.jpg",
        "alt": "The Quiet Garden cover",
        "width": 600,
        "height": 900,
        "sizes": { "medium": "https://your-site.com/…-200x300.jpg", "medium_large": "…" }
      },
      "buy_url": "https://example.com/books/the-quiet-garden"
    }
  }
]
```

The image object also carries the title, caption, file size and every image size; it is trimmed here.
Note that **`pages` is a string** (`"248"`) with `acf_format=standard`, while it is a number without it,
so the code converts it with `Number()`.

## How it fits together

- **The HTML is a shell.** `index.html` has an empty list and a `<template>` for one book card;
  `book.html` has an empty article.
- **One file talks to WordPress.** `js/wordpress.js` holds the fetch helper and one function per query.
  Every book request adds `acf_format=standard`, so the pages get ready-to-use images.
- **Each page script fills its page.** `js/books.js` copies the card template once per book;
  `js/book.js` reads `?slug=` from the address and fills in the article, using the cover's own alt text.
- **Titles and content arrive as HTML.** Titles are converted to plain text before they go into
  `textContent`; the post body is your own site's HTML and is inserted as it is.

## Plain JavaScript or Next.js?

Here the visitor's browser builds each page, so search engines see "Loading…" first and the content only
after the script runs. That suits small sites, a widget inside another site, and learning the API. For a
full website where search ranking and first load matter, [Next.js + ACF](./nextjs-acf.mdx) builds
the same pages on the server.
