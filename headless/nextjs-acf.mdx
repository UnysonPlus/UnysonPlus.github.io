# Headless WordPress with Next.js, ACF and CPT UI

The most common headless WordPress stack: **Custom Post Type UI** for the content type, **Advanced Custom
Fields (ACF)** for the fields, and a **Next.js** front end that builds a page per post ahead of time and
refreshes from WordPress in the background.

The example is a small book site: a list of books, and a page per book with its own title, description
and cover as page metadata.

<p><small>The same front end with Unyson+ instead of the two plugins:
[Next.js + Unyson+](./headless-nextjs-unysonplus.mdx). Without a framework:
[JavaScript + ACF](./headless-javascript-acf.mdx).</small></p>

## 1. Before you start

You need:

- **A WordPress site** you can log in to as an administrator: on any host, or on your own computer (LocalWP, XAMPP). It needs to be reachable from wherever the front end runs.
- The free plugins **Custom Post Type UI** and **Advanced Custom Fields** (step 2 installs them).
- **Node.js 18.18 or newer** and a terminal. The front end is a Next.js 15 project; `npm install` fetches everything else.

About 15 minutes for WordPress, and 10 for the front end.

## What the API returns

The fields arrive under **`acf`**. With **`acf_format=standard`** in the request, ACF returns each field
in its Return Format, so the cover is an object with its URL, width, height, alt text and image sizes
(without it, just the attachment ID). One catch: with `acf_format=standard`, **Number fields come back as
strings** (`"pages": "248"`), so the types allow both and the pages convert with `Number()`.

```json
"acf": {
  "subtitle": "A year among the weeds",
  "book_author": "Sam Rivera",
  "pages": "248",
  "cover_image": { "id": 3659, "url": "https://your-site.com/…/quiet-garden-cover.jpg", "alt": "The Quiet Garden cover", "width": 600, "height": 900, "sizes": { "…": "…" } },
  "buy_url": "https://example.com/books/the-quiet-garden"
}
```

## How it fits together

- **One file talks to WordPress.** `lib/wordpress.ts` describes the ACF fields as TypeScript types
  (including the image object), adds `acf_format=standard` to every book request, and has one function
  per query. Pages never build REST URLs themselves.
- **Pages are server components.** They `await` those functions, so the HTML that reaches the browser
  (and search engines) already holds the content.
- **Built ahead of time, refreshed in the background.** `generateStaticParams` builds every book page;
  `revalidate: 300` fetches fresh data at most every five minutes. To update the moment an editor
  publishes, call a revalidation route from a WordPress webhook.
- **Metadata from ACF.** `generateMetadata` uses the subtitle as the description and the cover, with its
  size and alt text, as the sharing image.

## Next.js or plain JavaScript?

Next.js builds pages on the server, which suits full websites where search ranking and first load
matter. For a small site, a widget, or to learn the API, [JavaScript + ACF](./headless-javascript-acf.mdx)
does the same in the browser with no build step.
