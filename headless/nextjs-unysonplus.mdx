# Headless WordPress with Next.js and Unyson+

The same Next.js front end as [Next.js + ACF](./nextjs-acf.mdx), with **one plugin instead of
two**: Unyson+'s Post Types extension registers the content type, and its Custom Fields extension adds
the fields and puts them in the REST API. The front end builds a page per post ahead of time and
refreshes from WordPress in the background.

<p><small>Without a framework: [JavaScript + Unyson+](./javascript-unysonplus.mdx). The WordPress
side in more detail, including a version defined in code: [Headless with Unyson+](./unysonplus.mdx).</small></p>

## 1. Before you start

You need:

- **A WordPress site** you can log in to as an administrator: on any host, or on your own computer (LocalWP, XAMPP). It needs to be reachable from wherever the front end runs.
- **Unyson+** installed and active (download `unysonplus.zip` from the [installation guide](/installation) and upload it under Plugins → Add New → Upload Plugin).
- **Node.js 18.18 or newer** and a terminal. The front end is a Next.js 15 project; `npm install` fetches everything else.

About 15 minutes for WordPress, and 10 for the front end.

## What the API returns

The fields arrive under **`unysonplus_fields`**, with no extra query parameter:

```json
"unysonplus_fields": {
  "subtitle": "A year among the weeds",
  "book_author": "Sam Rivera",
  "pages": 248,
  "cover_image": { "attachment_id": 3630, "url": "//your-site.com/wp-content/uploads/2026/10/quiet-garden-cover.jpg" },
  "buy_url": "https://example.com/books/the-quiet-garden"
}
```

`pages` is a number. The image URL starts with `//`, so `absoluteUrl()` in `lib/wordpress.ts` gives it
your site's scheme. Image sizes and alt text in the response are on the [Headless extension
roadmap](/extensions/headless).

## How it fits together

- **One file talks to WordPress.** `lib/wordpress.ts` knows the API's address, describes the Unyson+
  fields as TypeScript types, and has one function per query. Pages never build REST URLs themselves.
- **Ask only for the fields you use** with `?_fields=`, so responses stay small.
- **Pages are server components.** They `await` those functions, so the HTML that reaches the browser
  (and search engines) already holds the content.
- **Built ahead of time, refreshed in the background.** `generateStaticParams` builds every book page;
  `revalidate: 300` fetches fresh data at most every five minutes. To update the moment an editor
  publishes, call a revalidation route from a WordPress webhook (on the [roadmap](/extensions/headless)).
- **Metadata from WordPress.** `generateMetadata` turns the book's title, subtitle and cover into the
  page title, description and sharing image.

## What changes from the ACF version

| | ACF + CPT UI | Unyson+ |
|---|---|---|
| Plugins | Two | One (two extensions) |
| Fields in the response | `acf` | `unysonplus_fields` |
| Extra query parameter | `acf_format=standard` | None |
| `pages` | String with `acf_format=standard` | Number |
| Cover image | Object with URL, sizes, alt | ID and `//` URL (sizes and alt planned) |

Everything else (routing, revalidation, metadata) is identical: compare the two `lib/wordpress.ts` files.
